# Originality is a decision, then a review

Lazarus's signature is a standard of authorship. It is not a house palette, a serif headline, a 3D statue, or an obligatory experimental interaction. The studio's own surrealist identity is not a client template.

## Before drawing a page

1. Identify what the visitor needs to **do**, what the client can **prove**, and which material is missing. Keep uncertain facts out of published claims.
2. Write a thesis that explains why this particular content needs this particular structure. “Premium, modern, elegant” is not a thesis.
3. Develop seven structural proposals. Compare **content order, reading grammar and interaction**, not seven moodboards. Keep recognizable navigation when it helps the reader; difference is not a reason to make a task harder.
4. Name one signature decision grounded in a verified fact: a way of comparing work, showing a process, annotating an artifact, or reading a body of knowledge. Describe the reader benefit and the usable fallback. A quiet site can have a strong signature.
5. Select a direction with its cost. Reject the other six for specific reasons. Use the same genuine words in three typographic specimens before building the chosen direction.

Record these decisions in [design-contract.json](../templates/design-contract.json). [Direction Room](../direction-room/) helps edit the brief, compare the seven structures and export the record; it does not generate the concepts for you.

## Make the content unmistakably theirs

| Surface | Author a decision | Reject when |
| --- | --- | --- |
| Opening | Lead with the strongest useful fact, artifact or task. A hero is optional. | Changing a name makes it fit an unrelated business. |
| Copy | Use the client's vocabulary, concrete nouns, real constraints and a clear next action. | “Elevate”, “unlock”, “crafting digital experiences” or similar phrases substitute for an actual proposition. These are review signals, not banned words. |
| Composition | Assign prominence according to evidence; vary density only when the narrative needs it. | Every section becomes the same three equal cards. |
| Images | Specify subject, origin, rights, crop, focal point and caption before making or selecting an asset. | Decorative imagery stands in for real work, a real person, results or endorsements. |
| Type | Match reading tasks and language; test actual long words and real paragraphs. | Changing font names is the whole art direction. |
| Interaction | State trigger → state change → visitor benefit → keyboard/touch/static fallback. | A visitor has to wait, drag or watch a scene to access essential content. |
| Rhythm | Show a deliberate transition between introduction, evidence and action. | Every section uses the same entrance animation or scale. |
| Detail | Connect captions, separators, focus, empty states and errors to the same rules. | “Premium” decoration conceals a broken or incomplete product. |

Generated imagery may be an explicitly illustrative asset when appropriate. Never use it as evidence of a real built project, employee, product result or credential. Reuse licensed primitives and conventional controls freely; author the content relationships and dominant composition.

## Review at the point where sameness becomes expensive

**Before full build:** compare the seven content orders and reading grammars. If two proposals have the same structure, explain the functional difference or replace one. The contract tool catches exact normalized duplicates; a person must judge semantic duplicates.

**After the first real section:** render an opening plus one substantial evidence section on desktop and mobile. Remove brand name, color and custom fonts. Check whether the work and the reader's task still lead. Repair the concept here, before making more sections.

**Before delivery:** compare the skeleton against available previous Lazarus projects. Repeated task conventions can be justified; repeated dominant compositions for unrelated clients need revision. Record the comparison, or explicitly state that previous work is unavailable. Do not invent a comparison set.

## Three different conclusions

- **Contract complete:** required decisions and referenced artifacts are present. This is what the command-line gate can check.
- **Rendered checks recorded:** the declared viewport/state evidence exists and names a reviewed source commit. A tool cannot establish that a screenshot was honestly captured or that the prose in a review is true.
- **Design accepted:** actual pages were reviewed for identity, usefulness and craft; independent feedback is recorded if available. No script certifies originality, detects AI authorship or guarantees a visitor's opinion.

Never convert the number of completed fields into an “originality score”. Missing independent review is an explicit limit, not a fabricated pass. All critical accessibility, factual, rights and functional issues must be fixed before release.

## Corrections become project memory

Record `observed problem → structural cause → change → evidence after correction`. Carry the principle to future projects, not the palette or layout. A client rejecting giant type does not create a universal ban on giant type. A successful archive does not make the next client's website an archive.
