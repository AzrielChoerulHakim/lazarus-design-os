# Scroll Lab — Original progressive-enhancement examples

Open `index.html` or serve the repository from its root: `python3 -m http.server 8000` → `http://localhost:8000/scroll-lab/`.

What is **implemented and inspectable** here:

1. **S01 Reading Progress Rail**: optional JS representation of actual page progress. Not a false milestone counter; hidden in reduced motion.
2. **S02 Scroll-Synced Chapter Index**: plain fragment navigation with an enhanced active `aria-current` status. Does not depend on JS for operation.
3. **S03 Native Snap Chapter Strip**: direct touch/trackpad/keyboard scrolling, proximity snapping and functional fragment links. No wheel capture.
4. **S04 Sticky Evidence Exchange**: semantic prose sequence and a decorative sticky illustration derived from a single active stage ID. The stage becomes static on mobile, reduced motion and short height.
5. **S06 SVG Journey Trace (visual proof)**: a visible baseline vector path with optional feature-detected CSS view timeline. This is not a geography map or a complete production recipe.

These demos deliberately use **synthetic, clearly labelled sample content** and original CSS shapes. They are not evidence of real client work, not a source asset redistribution, and not fifteen browser-verified production widgets. Every other entry in the registry is a documented research/engineering recipe; it has **not** been built as a runnable example here.

Browser QA still requires real interaction, screenshots, different engines/devices and focus/assistive-technology inspection. Node unit tests inspect the selector/decision contract, not the visual quality of this demo.
